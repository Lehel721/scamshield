# ScamShield — Explainable, Obfuscation-Robust SMS Scam Detection for India

NLP mini-project. Builds on Ozoh et al. (2025) (SMS spam, TF-IDF + MLP) and extends it with
Indian-context scams, obfuscation-robustness evaluation and retrieval-based explanations
(inspired by SmishX, Wang et al., SOUPS 2025).

## Pipeline
SMS -> preprocessing (URL/phone/amount tokens, optional normalization) -> word+char TF-IDF -> Logistic Regression
-> red-flag rules + knowledge-base retrieval (TF-IDF cosine) -> explanation + advice.

## Experiments
| Model | Meaning |
|---|---|
| A | Baseline: classic SMS data only (paper replication style) |
| B | + Indian-context training data |
| C | + Text normalization defence (undoes leetspeak, homoglyphs, zero-width chars, spacing, URL tricks) |
| D | + Adversarial augmentation (attacked copies in training) |
| E | ScamShield: normalization + adversarial augmentation |

Attacks: leetspeak, homoglyph, zero-width, spacing, URL obfuscation, combined.

## Run
```bash
python -m venv venv && venv\Scripts\activate     # Windows (Linux/macOS: source venv/bin/activate)
python -m pip install -r requirements-dev.txt
python src/build_indian_data.py     # builds Indian train/test CSVs
python src/train.py                 # trains A-E, robustness suite, retrieval eval
streamlit run app.py                # demo (press Enter at the email prompt)
python src/bert_train.py            # OPTIONAL DistilBERT (pip install torch transformers)
```
Results are written to `results/` (metrics.csv, robustness.csv, plots, retrieval.json).

## Web app (Vercel)
The deployed version replaces Streamlit (which Vercel cannot host) with a static page plus Python serverless functions that load the same trained models:

| Path | What it is |
|---|---|
| `public/index.html` | Front end (same design as the Streamlit demo) |
| `api/analyze.py` | `POST /api/analyze` `{"message": "...", "attack": "None"}` → verdict, scores, red flags, advice, KB sources |
| `api/metrics.py` | `GET /api/metrics` → evaluation tables from `results/` |
| `src/service.py` | Shared analysis logic (no Streamlit/pandas) |
| `requirements.txt` | Minimal runtime deps for Vercel; versions pinned to match the pickled models |

On Vercel, set the project's **Root Directory** to `scamshield`. If you retrain with different library versions, update the pins in `requirements.txt` to match.

## Limitations (state these in the report)
- Indian training data is template-generated (synthetic); the 79-message test set is hand-written by the project authors and small, so near-perfect scores are optimistic.
- Retrieval keywords were written with these scam types in mind, so hit@k is optimistic.
- Explanations are template-based from a fixed knowledge base, not generated by an LLM.
- Verify helpline and portal details (1930, cybercrime.gov.in, 1909, Sanchar Saathi) before citing.
